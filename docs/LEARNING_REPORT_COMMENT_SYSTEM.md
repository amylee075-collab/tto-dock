# 또독 학습 리포트 코멘트 시스템 명세

## 1. 목적

학습 리포트 코멘트 시스템은 사용자의 읽기 활동 결과를 분석하여 학습 상태를 해석하고, 맞춤형 피드백 메시지를 생성하는 규칙 기반 시스템이다.

리포트는 다음 2개 영역으로 구성된다.

1. 기본 학습 리포트 총평
2. 영역별 결과 피드백

기본 학습 리포트 총평은 다음 요소를 다룬다.

- 읽기 속도
- 읽기 시간
- 퀴즈 정답률

영역별 결과 피드백은 다음 4개 영역을 다룬다.

- 어휘력
- 이해력
- 표현력
- 사고력

---

## 2. 시스템 구조

학습 리포트 코멘트는 다음 3단계로 생성된다.

1. 학습 결과 데이터 수집
2. 조건 평가(`rule evaluation`)
3. 메시지 선택 및 조합

최종 출력 구조는 다음과 같다.

```ts
type LearningReportComment = {
  summaryComment: string;
  speedComment: string;
  timeComment: string;

  vocabularyFeedback: {
    good: string;
    improve: string;
    tip: string;
  };

  comprehensionFeedback: {
    good: string;
    improve: string;
    tip: string;
  };

  expressionFeedback: {
    good: string;
    improve: string;
    tip: string;
  };

  thinkingFeedback: {
    good: string;
    improve: string;
    tip: string;
  };
};
```

## 3. 입력 데이터 정의

### 3.1 기본 학습 데이터

| 필드 | 설명 |
|------|------|
| `readingCpm` | 읽기 속도(CPM) |
| `readingDurationSec` | 읽기 시간(초) |
| `quizCorrect` | 퀴즈 정답 수 |
| `quizTotal` | 퀴즈 전체 문제 수 |

추가 계산값:

```ts
const quizAccuracy = Math.round((quizCorrect / quizTotal) * 100);
```

### 3.2 영역별 분석 데이터

| 필드 | 설명 |
|------|------|
| `coreWordCorrect` | 핵심 단어 정답 여부 |
| `synonymRecognition` | 유사어 인식 성공 여부 |
| `vocabContextAccuracy` | 문맥 단어 문제 정답률 |
| `readingQuizAccuracy` | 독해 문제 정답률 |
| `summaryLength` | 요약 글자 수 |
| `summaryKeywordCount` | 요약 내 핵심어 포함 개수 |
| `summarySentenceVariety` | 문장 다양성 점수 |
| `inferenceAccuracy` | 추론형 문제 정답률 |
| `thinkingNoteQuality` | 생각노트 품질 점수 |

---

## 4. 기본 학습 리포트 평가 규칙

### 4.1 읽기 속도 구간 정의

| 구간 | CPM |
|------|-----|
| `slow` | `<= 300` |
| `stable` | `301 ~ 500` |
| `fast` | `501 ~ 700` |
| `very_fast` | `>= 701` |

### 4.2 정답률 구간 정의

| 구간 | 정답률 |
|------|--------|
| `high` | `>= 80` |
| `medium` | `60 ~ 79` |
| `low` | `<= 59` |

---

## 5. 총평 메시지 규칙

총평 메시지는 `정답률 -> 속도 -> 시간` 순서로 해석한다.

### 5.1 정답률 높음(`>= 80`)

| 속도 조건 | 총평 메시지 |
|----------|-------------|
| 안정/빠름 | 내용을 잘 이해하면서 안정적으로 읽었어요. 읽기 속도와 이해의 균형이 좋아요. |
| 느림 | 천천히 읽었지만 내용을 정확하게 이해했어요. 꼼꼼하게 읽는 힘이 돋보였어요. |
| 매우 빠름 | 빠르게 읽으면서도 내용을 잘 이해했어요. 집중력이 아주 좋았어요. |

### 5.2 정답률 보통(`60 ~ 79`)

| 속도 조건 | 총평 메시지 |
|----------|-------------|
| 빠름 | 읽는 속도는 좋았지만 중요한 내용을 조금 놓쳤을 수 있어요. 핵심 문장을 조금 더 의식하며 읽어 보세요. |
| 안정 | 전체적인 내용은 잘 따라왔어요. 핵심 내용을 조금 더 또렷하게 잡아보면 좋아요. |
| 느림 | 차분하게 읽으려는 모습이 좋았어요. 중요한 정보를 조금 더 정리해 보면 좋아요. |

### 5.3 정답률 낮음(`<= 59`)

| 속도 조건 | 총평 메시지 |
|----------|-------------|
| 빠름 | 조금 빨리 읽어서 중요한 내용을 놓쳤을 수 있어요. 다음에는 핵심 문장을 생각하며 읽어 보세요. |
| 안정 | 끝까지 읽었지만 내용 이해는 조금 더 연습이 필요해요. 중심 내용을 다시 정리해 보면 도움이 될 거예요. |
| 느림 | 천천히 읽으려 노력했어요. 문단마다 어떤 내용인지 정리하며 읽어 보세요. |

---

## 6. 읽기 시간 보조 메시지

읽기 시간은 총평을 보조하는 메시지로 사용한다.

| 시간 해석 | 메시지 |
|----------|--------|
| 짧은 시간 | 짧은 시간 안에 읽기를 마쳤어요. |
| 적정 시간 | 집중해서 끝까지 잘 읽었어요. |
| 오래 걸림 | 시간을 들여 끝까지 읽은 점이 좋아요. |

추가 규칙:

- 읽기 시간이 짧고 정답률이 낮은 경우에는 `조금 서둘러 읽었을 수 있어요.`를 추가한다.

---

## 7. 영역별 결과 코멘트 구조

각 영역은 동일한 구조를 따른다.

```ts
type AreaFeedback = {
  good: string;
  improve: string;
  tip: string;
};
```

세 필드의 의미는 다음과 같다.

- `good`: 잘한 부분
- `improve`: 아쉬운 부분
- `tip`: 다음 행동 제안

---

## 8. 어휘력 평가 규칙

### 8.1 판단 기준

| 조건 | 결과 |
|------|------|
| 핵심 단어 정답 + 문맥 문제 `>= 80` | 높음 |
| 핵심 단어 정답 + 문맥 문제 `>= 60` | 보통 |
| 핵심 단어 오답 | 낮음 |

### 8.2 잘한 부분 메시지

- 글의 중요한 낱말을 정확하게 찾았어요.
- 문맥 속에서 단어 뜻을 잘 이해했어요.
- 핵심어를 잘 잡아내는 힘이 좋아요.

### 8.3 아쉬운 부분 메시지

핵심어 미정답:

- 글에서 가장 중요한 단어를 찾는 연습이 더 필요해요.

문맥 단어 약함:

- 단어의 뜻을 문장 속에서 이해하는 연습을 더 해보면 좋아요.

### 8.4 다음 행동 제안

- 모르는 단어가 나오면 앞뒤 문장을 함께 읽어 보세요.

---

## 9. 이해력 평가 규칙

### 9.1 판단 기준

| 정답률 | 평가 |
|--------|------|
| `>= 90` | 매우 좋음 |
| `70 ~ 89` | 좋음 |
| `50 ~ 69` | 보통 |
| `<= 49` | 낮음 |

### 9.2 잘한 부분

- 글의 중심 내용을 아주 잘 이해했어요.
- 사건의 흐름을 정확하게 파악했어요.

### 9.3 아쉬운 부분

- 세부 내용에서 조금 헷갈린 부분이 있었어요.
- 내용을 다시 한 번 천천히 정리해 보면 좋아요.

### 9.4 다음 행동 제안

- 읽고 난 뒤 한 문장으로 내용을 정리해 보세요.

---

## 10. 표현력 평가 규칙

### 10.1 판단 기준

| 조건 | 평가 |
|------|------|
| 핵심어 포함 + 적정 길이 | 높음 |
| 길이만 충족 | 보통 |
| 핵심어 부족 | 낮음 |

### 10.2 잘한 부분

- 중요한 내용을 빠뜨리지 않고 잘 정리했어요.
- 자신의 문장으로 내용을 자연스럽게 표현했어요.

### 10.3 아쉬운 부분

요약이 짧은 경우:

- 내용을 조금 더 자세히 써 보면 좋아요.

요약이 긴 경우:

- 핵심 내용만 남겨 더 간단히 정리해 보세요.

핵심어가 부족한 경우:

- 요약에 중요한 단어가 조금 더 들어가면 좋아요.

### 10.4 다음 행동 제안

- 요약하기 전에 중요한 단어를 먼저 떠올려 보세요.

---

## 11. 사고력 평가 규칙

### 11.1 판단 기준

| 조건 | 평가 |
|------|------|
| 추론 정답률 `>= 70` + 노트 품질 높음 | 높음 |
| 둘 중 하나만 충족 | 보통 |
| 둘 다 낮음 | 낮음 |

### 11.2 잘한 부분

- 글에 직접 나오지 않은 내용까지 생각해 보았어요.
- 자신의 생각을 근거와 함께 잘 표현했어요.

### 11.3 아쉬운 부분

- 왜 그렇게 생각했는지 이유를 더 자세히 써 보면 좋아요.

### 11.4 다음 행동 제안

- `나는 ~~라고 생각한다. 왜냐하면 ~~ 때문이다.` 형식으로 생각을 써 보세요.

## 12. 톤앤매너 규칙

코멘트 시스템은 다음 원칙을 따른다.

- 긍정 중심 피드백
- 비난 표현 사용 금지
- 개선 제안 중심 표현 사용
- 속도보다 이해 강조
- 모든 개선 메시지에 행동 제안 포함

예시:

- `틀렸어요` 대신 `조금 더 연습하면 좋아요`
- `읽는 속도가 느립니다` 대신 `천천히 꼼꼼하게 읽는 힘이 좋아요`

## 13. 구현 가이드

### 13.1 권장 처리 순서

1. 입력 데이터 정규화
2. 파생값 계산
3. 속도/정답률/시간 구간 판정
4. 영역별 수준 판정
5. 메시지 템플릿 선택
6. `LearningReportComment` 구조로 조합

### 13.2 권장 파생값

```ts
const quizAccuracy = Math.round((quizCorrect / quizTotal) * 100);
const speedBand =
  readingCpm <= 300 ? "slow" :
  readingCpm <= 500 ? "stable" :
  readingCpm <= 700 ? "fast" :
  "very_fast";

const accuracyBand =
  quizAccuracy >= 80 ? "high" :
  quizAccuracy >= 60 ? "medium" :
  "low";
```

### 13.3 권장 파일 분리

- `lib/report-comment-rules.ts`: 규칙 정의
- `lib/report-comment-types.ts`: 타입 정의
- `lib/report-comment-builder.ts`: 최종 코멘트 조합 함수

## 15. 결론

본 코멘트 시스템은 읽기 속도, 퀴즈 정답률, 요약 및 사고 활동 결과를 종합 분석하여 사용자의 읽기 능력을 긍정적으로 해석하고, 다음 학습 행동을 제안하는 피드백을 제공하는 것을 목표로 한다.
